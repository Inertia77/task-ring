# TaskRing 设计系统维护规范（2026-11）

本规范描述当前前端已实现的共同约定，供后续精修、代码审查与可视回归使用。**不要为统一外观而改变任务状态、存储、ID、完成统计或用户游玩策略。**

## 来源与 CSS 优先级

- `assets/css/tokens.css` 定义共享颜色、间距、圆角、字号与动效基础 Token。
- `assets/css/main.css` 控制样式导入顺序；2026-11 主分支的最终响应式层为 `mobile-execution.css`，后续的 `app-design.css` 则处理统一应用外观与部分最终样式。
- `app-design.css` 也重新定义部分 `:root` Token；其值在同一层叠条件下优先于 `tokens.css`。调整 Token 时必须核对最终计算样式，不能只改 `tokens.css` 并假定生效。
- 新的局部修复应在所属模块的既有层或最小维护范围内进行；禁止无证据追加大规模通用 `!important`。
- CSS 文件是否废弃必须由页面运行时加载、DOM 选择器命中与截图对照证明，不能只看文件名中的时间戳。

## 2026-11-05 作战终端视觉方向（Operations HUD）

TaskRing 首页和六模块采用原创二游风格任务终端：暗色指挥顶栏、金色当前目标、青色辅助状态、浅色任务面板、细线进度条与小型数字标签。强调“查看任务 → 执行 → 完成反馈”，而非叠加背景故事、美术插图或复杂二级入口。

- 入口与导航：`assets/css/operations-hud.css` 是 `app-design.css` 后的最后视觉层；Header 与六模块 Command Rail 使用暗色金属/金色选中态；触控命中区不得减少。
- 每日：保留进度指标和三种任务视图；任务组以 squad header 呈现，Checkbox 保持直达。
- 游戏：保留日常/周常/限时子页与分组；T1/T2/T3 在既有身份语义上用金色、青色和中性边条区分；不制造虚假的强制解锁。
- 六模块卡片：浅色、紧凑、统一的面板边缘和行动按钮；状态优先使用原有文字/图标，不仅靠颜色。
- 移动端：Header 不隐藏 GitHub 同步状态；底部固定六模块导航，避开系统安全区；没有新增高占屏大横幅。
- 离线：`service-worker.js` 的 shell 列表必须包含新 CSS。版本迭代同时更新 `index.html` 缓存参数与 shell 版本。
- 易用性：在 `prefers-reduced-motion` 下关闭非必要进度/导航动效；保证键盘焦点和滚动保持；不依赖外部图片、视频或外部字体请求。

## 共享基础

| 主题 | 已有语义 | 守则 |
|---|---|---|
| 画布/卡片 | `--color-canvas`, `--color-panel`, `--color-card`, `--color-panel-soft` | 主内容使用低噪声表面；数据优先，不增加纹理背景或额外大边框 |
| 文本 | `--color-ink`, `--color-muted` | 正文与辅助文字层级明确；状态不能仅靠颜色 |
| 状态 | `--color-success`, `--color-warning`, `--color-danger`, `--color-info` | 显式的文字/图标与颜色配合，不因重新配色而改动完成/等待含义 |
| 间距 | `--space-1` … `--space-8` (4–32px) | 优先复用，避免零散增添新距离 |
| 交互 | `--tap-size`, `--ui-control-size` (44px) | 手机高频按钮尽量提供 44×44px 命中区域 |
| 圆角/阴影 | `--radius-sm/md/lg`, `--shadow-card` | 阴影适度，仅用于信息层级而不是装饰 |
| 动效 | `--motion-fast/ui/slow` | 尊重 `prefers-reduced-motion`，不能让操作动画阻碍输入 |

## 六模块可辨识性

- **每日**：紧凑的待办执行流；一键勾选、计时、子任务和链接可立即发现。
- **周计划**：分类、目标与本周实际进度，允许卡片内容长短不同；水平分类 Tab 不回跳。
- **生活改善**：训练／饮食／睡眠等生活流程；日历与状态信息不遮挡大触控目标。
- **游戏作战区**：日常、周常、限时・周期三子页；T1/T2/T3、必做/可选、剧情重点分别展示；T3 永远允许勾选与撤销。
- **时间账本**：计时中/已暂停、补记、配额与历史；数字使用稳定易读的单位，浮动条不挡底栏。
- **资料库**：检索与档案组，长标题换行而不破坏布局；空结果提供下一步操作。

## 响应式及导航约束

- 现有断点包括 359/360、700、900/901、1024、1050、1100px 等边界；重构前应优先运行现有真实浏览器矩阵，而不是发明更多断点。
- 一级模块切换显示新模块标题与筛选，内部筛选只刷新本地任务区域。横向 Tab 的 `scrollLeft`、全页合理滚动位置、输入焦点与未保存草稿是可测试状态。
- 全部导航、弹窗与滚动相关变更须运行 Chromium 和 WebKit；参见 `tests/browser/` 下相关规范与 `docs/audits/uiux-2026-11-05-implementation.md`。
- Dialog 的焦点应留在对话框内，关闭后回到起始操作。按钮提供可访问名称，焦点可见，短屏幕与系统字体放大不能遮挡保存按钮。
- `service-worker.js` 更新必须保留未保存草稿保护；不要清理同源中不属于 TaskRing shell 的缓存。

## 每次 UI PR 的检查清单

1. 复现问题（具体浏览器、宽度、界面状态、操作步骤）并记录代码证据。
2. 检查计算样式来源和重复 CSS 命中；选择最小修复，不改变业务规则。
3. 用隔离假数据生成 `before` 与 `after` 截图，覆盖受影响的六大模块或解释无关模块不受影响的依据。
4. 补充回归测试：滚动、焦点、草稿、Checkbox、视口溢出和重要可访问行为。
5. 通过 Node、Chromium、WebKit 的 CI 后才合并；部署后核验正式 URL 与构建版本。

该文件是**维护约定**而非“全站所有组件已达到 AA”的证明；未经测量的对比度/辅助技术问题继续留在审计待办中。
